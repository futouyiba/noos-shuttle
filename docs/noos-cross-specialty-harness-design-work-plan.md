# NOOS 跨专业 Harness — 工作约定与推进计划

> 类型：本设计任务的工作方式、进度与恢复入口；不是产品规范或执行授权。
> 配套：[当前产品设计](noos-cross-specialty-harness-product-design.md) · [决策依据与历史](noos-cross-specialty-harness-decision-record.md)

## 1. 持续工作约定

用户原文：

> “我一边讨论，你一边把一些点就往设计文档里面去改。然后改着改着达到了一个相对稳定的程度就形成提交，防止聊着聊着把前面的东西又忘了。”

文档卫生要求原文：

> “不同种类的文档要分开。例如负责设计稿的，负责历史记录的，等等。”

执行方式：

- 每轮聚焦一个主题，及时整理共识、候选和未决项，不等整段讨论结束才沉淀。
- 确认必须有实际来源；用户询问、要求继续或批准讨论计划，不等于接受全部建议。
- 文档承接跨会话记忆，不声称聊天平台已保存永久 memory；不默认重放整个对话。
- 稳定的一组内容可做本地检查点提交；提交次数不等于阶段完成数，候选检查点不等于 APPROVE。
- 不自动 push、创建远端 PR、合并、部署、关闭任务或进入产品实现。需要时按授权和[仓库协作规范](https://github.com/futouyiba/noos_docs/blob/main/docs/agent-workflow.md)执行。
- 稳定设计接受独立评审；触及权威契约的差异另行裁定，不自我批准。

## 2. 文档分工与维护规则

| 文档 | 只负责什么 | 不放什么 |
| --- | --- | --- |
| 当前产品设计 | 现行方向、候选方案、职责、场景、未决问题与验收关注点 | 聊天流水、被撤回方案全文、每轮提交说明 |
| 决策依据与历史 | 必要原文、决定和修订理由、重要替代方案、案例证据、版本锚点 | 复制一份完整当前设计，或把每次“继续”记成事件 |
| 本工作计划 | 协作约定、阶段状态、下一讨论入口与交付门禁 | 产品细节和设计结论的第二份真源 |

更新时遵循：

1. 修改对应主题的既有段落，不在文末不断追加“又一轮分析”。
2. 已解决问题从当前待决清单移出；保留必要的决定依据，而非让新旧结论并排都像有效。
3. 被取代的方案在历史中标明状态和原因，当前设计只保留有效表述。
4. 同一事实只维护一处正文，其余用链接；历史不能覆盖当前规范。
5. 文件按职责拆分，不按聊天轮次或每个小观点建文件；不提前拆出空白 schema、接口或独立章节文档。
6. 使用稳定标题作导航；Git 保存逐行历史，文档只记录有意义的设计变化。
7. 整理只改变表达与位置，不借机改变确认状态、授权范围或既有契约。

## 3. 四阶段推进

| 阶段 | 状态 | 目标与退出条件 |
| --- | --- | --- |
| 1. 定位与边界 | 已沉淀，未独立评审 | 记录用户共识、职责边界、既有依据和开放问题 |
| 2. 真实场景与优先级 | 进行中 | 补齐三个场景的实际旅程，经用户确认后明确首版必需能力、优先级与后续扩展 |
| 3. 工作记忆与协作规则 | 提前探索，未完成 | 明确信息层次、角色职责、对象对应及需要裁定的差异 |
| 4. 交互与首个切片 | 未开始 | 选择优先场景，形成交互、异常恢复、验收与实现边界，之后才讨论实现授权 |

第二阶段三个场景：

- A：长期设计讨论沉淀后，换新对话继续。尚需实际迁移经历、丢失内容与重述成本。
- B：设计与开发或视觉角色之间交付并回传。目前深入 B1：开发遇到设计边界、用户来回传话。
- C：调研、设计、视觉探索、原型实现与验证反复迭代。尚需完整真实工作案例。

每个场景补齐用户目标、分工、必要上下文、交付、人工决定点、完成标准和失败恢复；不代填为已经验证的事实。

## 4. 当前恢复入口

已完成：初始定位沉淀、B1 痛点确认、四个历史请求过程推演；自动触发与忙碌不抢占方向有用户确认。

正在讨论：面向 Coding Agent 的设计支持，以及主讨论与有界工作会话的关系。用户尚未批准采用多会话委派架构，五类用途也只是候选分类。

下一步：基于当前设计稿的 Q2 / Q8 / Q9，讨论具体设计支持任务的职责、材料与自动处理条件。不再把已撤回的手动忙闲开关作为默认方案，也不提前假定独立工作会话已获授权。GitHub 分工和首版优先级仍待确认。

本轮文档分拆是维护方式修正，不是新产品决策；不创建新 Agent、watcher、后台自动化或运行时实例。

## 5. 验证与交付

文档修改检查本地链接、空白错误、状态一致性和变更范围；不运行与纯文档整理无关的构建。作者检查不是独立 review。

产品验收问题维护在当前设计稿，不在此重复。真实场景验证尚未执行，案例分析不能证明收益或平台能力。进入实现或集成前按相应流程重新检查证据与授权。
